## What this update does

The existing serial status loop feeds the validated ToF and gesture readings to
one SensorSampler. It uses the existing Occupancy tracker, now in its own
module, followed by ReflexController. PerceptionController receives their
observation. There is no second occupancy tracker or additional serial owner.

ReflexController proposes arrival, departure, deliberate gesture, and abrupt
close-approach events. It has no camera, servo, speech, LLM, network or database
capability. The observation build pauses automatic perception for **all** saved
camera policies, including EVENT_ONLY and AWARE. Policy selections are retained;
enabling live event perception belongs to Gate 3. Explicit capture, voice look
and explicit enrolment retain the existing CameraManager privacy guard.

The Vision page shows the current occupancy session, sensor health, proposal
count, quiet/background count, cached samples, missing/invalid samples,
cooldown suppression and recent proposals. A proposal is never an action.
Existing voice, reminders, manual controls and manual camera functions remain
available; they are not generated by the reflex observer.

## Evidence and session rules

- Existing occupancy defaults remain: arrival at <=900 mm over 2 seconds of
  distinct valid evidence; departure at >=1200 mm over 4 seconds. The deadband
  preserves the tracker decision. These distances require desk calibration.
- An occupancy session begins on confirmed OCCUPIED and ends on confirmed
  CLEAR. UNKNOWN, missing samples, sequence resets and short losses preserve
  that session. They never become a fabricated departure or a second arrival.
- Startup, host/device reconnect, settings/privacy resets, resume and stop
  explicitly reset the observation context. An existing session gets a
  `session_ended` record with the reason; this is not a detected departure.
- ToF is range/occupancy evidence, never identity or direction. A close approach
  can propose attention, not an invented left/right servo command.
- Initial close-approach calibration: a drop of >=250 mm within 2.5 seconds,
  ending <=350 mm, then a second distinct close sample after 0.25–2.5 seconds.
  A single spike is ignored. Rearm requires >=500 mm over two distinct samples
  spanning at least 1 second; proposals also have a 10-second cooldown.
- Gesture proposals require a new event sequence and event age <=1500 ms.
  The first observed sequence is a baseline; cached events are not replayed.
  New gesture proposals have a 3-second cooldown. They do not create a visit.
- Salience and confidence are deterministic tuning scores, not measured
  probabilities. They are initially arrival .80/.85, departure .65/.85,
  gesture .85/.90 and close approach .90/.80.

Only meaningful occupancy changes and reflex proposals are added to the existing
v4 event table. Occupancy-session IDs live in event evidence; they are not visual
presence-session foreign keys or identity claims. Raw sensor samples and
suppressed desk motion are not persisted.

The desktop export retains the latest aggregate snapshot and up to 120
allowlisted reflex proposals in a separate `reflex` section. Device-status spam
cannot displace those proposals. The export includes no conversation text,
images, face names or embeddings.

## One owner observation pass

1. Install this complete desktop update using `Install-Kadence.cmd`, then start
   Kadence using its usual shortcut. Open Ollama if it is not already running.
2. Keep Vision OFF and open **Vision → Sensor observations**. Leave the ToF zone
   clear for about 5 seconds, then sit in range for about 3 seconds. Expect one
   ARRIVAL proposal and an occupancy-session ID.
3. Work at the desk normally for 5–10 minutes. The background count should rise
   while the arrival count stays unchanged. There should be no reflex-driven
   capture, speech, greeting or head movement.
4. Make one deliberate gesture. Pause at least 3 seconds and make another.
   Expect one proposal per new gesture, without a new arrival or identity check.
5. Approach the sensor abruptly to within roughly 35 cm, then hold briefly.
   Expect one CLOSE_APPROACH proposal. Remaining close should not repeat it.
6. Leave beyond roughly 1.2 m for at least 4 seconds, then return within roughly
   0.9 m for at least 2 seconds. Expect DEPARTURE, then ARRIVAL with a new session.
7. Confirm a normal voice response and manual camera capture still work, then
   export diagnostics once. Send that file with any unexpected proposal or
   missed event; no screenshots of every step are needed.

## Rollback

Quit Kadence fully and run `Install-Kadence.cmd` from the accepted 0.4.0 package.
Both versions use schema v4; this update adds event records and does not migrate
the database or alter credentials. Keep Vision OFF when returning to 0.4.0:
that older build does not have the observation-mode automatic-perception pause.
